# Security Policy

## Supported Versions

| Version | Supported |
| ------- | --------- |
| 0.1.x   | Yes       |

As the project matures and new versions are released, this table will be updated to reflect which versions receive security fixes.

## Reporting a Vulnerability

**Do not use public GitHub issues to report security vulnerabilities.**

If you discover a security vulnerability in this project, report it privately through GitHub Security Advisories. To do so:

1. Navigate to the repository on GitHub.
2. Go to the **Security** tab.
3. Click **Report a vulnerability**.
4. Fill out the advisory form with as much detail as possible.

If you are unable to use GitHub Security Advisories, contact the maintainers directly through the contact information listed in MAINTAINERS.md.

### What to Include

When reporting a vulnerability, include the following information where possible:

- A description of the vulnerability and its potential impact.
- Steps to reproduce the issue, or a proof of concept.
- The version(s) of the project affected.
- Any suggested fixes or mitigations you are aware of.

## What to Expect

After you submit a report:

1. **Acknowledgment.** You will receive an acknowledgment within 7 days confirming that the report has been received.
2. **Assessment.** The maintainers will evaluate the report and determine the severity and scope of the vulnerability.
3. **Communication.** You will be kept informed of progress toward a fix. If the report is accepted, the maintainers will work with you to understand the issue fully before any public disclosure.
4. **Resolution.** A fix will be developed and released. Credit will be given to the reporter unless they prefer to remain anonymous.
5. **Disclosure.** Once a fix is available, a public advisory will be published describing the vulnerability and the remediation.

If the report is determined to be outside the scope of this project or not a valid vulnerability, you will be notified with an explanation.

## Scope

Security concerns relevant to this project include:

- Vulnerabilities in the reference implementation code.
- Issues in dependencies that affect the security of this project.
- Flaws in the judgment point specification that could lead to unsafe behavior in implementations.
- Configuration or deployment guidance in this repository that could lead to insecure setups.

The following are outside the scope of this policy:

- Vulnerabilities in third-party services or platforms not maintained by this project.
- Issues in software that merely uses or references this project but is not part of this repository.

## Responsible Disclosure

We ask that reporters follow responsible disclosure practices. Allow a reasonable amount of time for the vulnerability to be addressed before making any information public. We are committed to addressing valid reports promptly and transparently.
